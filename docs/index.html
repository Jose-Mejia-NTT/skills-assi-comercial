A · Cómo se implementa el pipeline (3 skills)

Cada skill del pipeline ejecuta pasos concretos y genera un artefacto. El paso de investigación usa graphify (grafo local, ~0 tokens).

01bcv-hu-context-analyzerPipeline · paso 1HU funcional → contexto técnico
Cómo se implementa
  1. Valida la HU (actor, acción, objetivo, CAs).
  2. Clasifica servicios (primary / secondary / omitted) con service-map.md.
  3. Investiga el código con graphify (máx 2 queries por servicio primario).
  4. Lee fragmentos puntuales y detecta gaps (tipo · bloquea · sugerencia).
  5. Escribe el artefacto.
Entrada → Salida

HU funcional + workspace → .context/hu-<codigo>.md

Rol: genera la base técnica de todo el flujo.

02bcv-dhu-writerPipeline · paso 2contexto → Historia Técnica (DHU)
Cómo se implementa
  1. Lee el contexto .context/hu-<codigo>.md.
  2. Rellena el template extendido (ibk-hu-technical-refinement): CAs, endpoints, mapa técnico, config externa, DoR/DoD.
  3. Documenta gaps y dudas con respuestas sugeridas (no pregunta en vivo).
  4. Auto-valida: ≥3 CAs, mapa técnico no vacío, DoR completo.
  5. Escribe el artefacto.
Entrada → Salida

.context/hu-*.md → hu-technical-refinement/HU-...-refined-....md

Rol: convierte el análisis en una spec accionable y estándar.

03bcv-hu-implementerPipeline · paso 3DHU → código (reporte y ramas feature)
Cómo se implementa
  1. Pre-valida la DHU (sin gaps bloqueantes, ≥3 CAs, mapa técnico).
  2. Descubre los skills disponibles en el workspace/usuario.
  3. Genera el reporte (dry-run por defecto) con columna Skill por tarea.
  4. En --apply: crea ramas feature/HU-... y aplica cambios.
  5. Ejecuta linter + tests (./mvnw verify).
  6. Indica si toca regenerar el grafo graphify (solo cambios estructurales).
  7. Nunca commitea ni pushea (revisión humana).
Entrada → Salida

DHU → reporte + ramas feature + código

Rol: ejecuta la spec; delega el “cómo codificar” a los skills de implementación.

B · Uso de graphify

Motor de investigación local que hace el flujo BCV eficiente en tokens.

🔍 Qué hace

Indexa el código en un grafo local (AST). bcv-hu-context-analyzer lo consulta con query / path / explain.

💰 Por qué

~85 % menos tokens (~70k → ~10k por HU). Consultas locales que no consumen LLM.

🔄 Cuándo actualizar

Solo en cambios estructurales: graphify <repo> --code-only; verifica con graphify check-update <repo>.

$ graphify query "registryOffice" --max 5 --graph <repo>/graphify-out/graph.json
$ graphify check-update <repo>   # ¿grafo desactualizado?
$ graphify <repo> --code-only     # regenerar grafo
