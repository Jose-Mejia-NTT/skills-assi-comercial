# Workflow

## 1. Read the context file

Open `.context/hu-<code>.md` generated by `bcv-hu-context-analyzer`.

If the file does not exist, stop and ask the user to run `bcv-hu-context-analyzer` first.

## 2. Validate context completeness

Verify the context contains:

- Metadata (code, actor, action, goal).
- Acceptance criteria.
- Business rules.
- Classified services (primary/secondary/omitted/to_confirm).
- Current technical flow.
- Key finding.
- Expected changes.
- Gaps.

If critical sections are missing, stop and report the problem.

## 3. Decide split or single DHU

Evaluate BEFORE writing:

- If the context describes multiple independent backend responsibilities, split into multiple DHUs (one per service or concern).
- If the expected changes produce more than 8 acceptance criteria, split into phases.
- Otherwise, produce a single DHU.

State the selected mode in the response.

## 4. Map context to DHU sections

| Context section | DHU section |
| --- | --- |
| Metadata / actor / action / goal | Title, short description, need, narrative |
| Acceptance criteria | Acceptance criteria (translated into technical, testable CAs) |
| Business rules | Business rules embedded in CAs or technical spec |
| Current flow + expected changes | TO BE flow + endpoint spec |
| Affected contracts | Endpoint(s) section |
| Migrations | Appendix — technical context |
| Gaps | Appendix — pending decisions (do not hide them) |
| Assumptions / risks | Appendix — technical context |

## 5. Write the DHU

Use [output-template.md](output-template.md) exactly.

Rules:

- Keep the narrative technology-agnostic (INVEST N).
- Put endpoints, HTTP codes, JSON schemas, and field names in the observable contract.
- Put stack details (Java, Spring Boot, etc.) only in the appendix technical context.
- Use English for all technical identifiers (field names, JSON keys, error codes).
- Use the user's language for human-readable text.

## 6. Persist the file

Save to:

```
<workspace-root>/hu-technical-refinement/HU-{identifier}-refined-{YYYYMMDDHHmm}.md
```

Create the folder if it does not exist.

## 7. Respond to the user

Return:

- Path to the generated file(s).
- Summary of the DHU(s).
- List of gaps moved to pending decisions.
- Suggested next steps.
